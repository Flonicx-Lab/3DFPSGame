# Unity C# 코드 리뷰 기준

## 리뷰 원칙

- 변경된 코드에서 실제로 발생할 가능성이 있는 문제를 우선한다.
- 취향 차이나 과도한 리팩터링을 필수 수정처럼 표현하지 않는다.
- 파일과 코드 위치, 원인, 결과, 수정 방법을 구체적으로 적는다.
- 변경과 무관한 기존 문제는 참고 사항으로 구분한다.
- 확실하지 않은 내용은 사실처럼 단정하지 않는다.
- 프로젝트 규모에 맞는 개선안을 제시한다.

## 중요도

- Critical: 크래시, 데이터 손상, 보안 문제
- High: 기능 오류나 심각한 성능 저하 가능성이 높은 문제
- Medium: 안정성, 확장성, 유지보수성 문제
- Low: 가독성, 이름, 코드 단순화 문제

## C# 확인 항목

- NullReferenceException과 컬렉션 범위 오류 가능성
- 이벤트 구독 해제와 IDisposable 정리
- 반복되는 박싱, 문자열 생성, LINQ 실행
- 불필요한 public 필드와 캡슐화 훼손
- 예외 처리, 비동기 취소, 중복 로직
- 이름만으로 역할을 알 수 있는지 여부
- 의미가 불명확한 숫자와 문자열의 직접 사용
- 단일 책임, 낮은 결합도, 높은 응집도

## Unity 확인 항목

- Update와 FixedUpdate의 반복 할당 및 탐색
- 물리 처리의 프레임 의존성
- Coroutine, Invoke, async 작업의 생명주기
- 이벤트 등록과 해제의 대칭성
- Inspector 필수 참조 검증
- Time.deltaTime과 고정 시간의 올바른 사용
- 반복되는 Instantiate와 Destroy
- 런타임 데이터와 원본 설정 데이터 분리

## 리뷰 결과 형식

### 총평

변경 목적과 전체 평가를 2~3문장으로 작성한다.

### 발견된 문제

각 문제에 중요도, 파일과 위치, 원인, 결과, 수정 제안을 포함한다.

### 설계 개선 제안

구조 문제가 명확할 때만 현재 문제, 개선 구조, 클래스 책임, 상호작용, 비용을 설명한다.

### 잘 작성된 점

실제로 잘 작성된 부분만 적는다. 문제가 없으면 확인 범위와 발견되지 않았음을 명시한다.
